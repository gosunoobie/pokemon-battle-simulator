# Poké Ball and faint audio

The user requested Poké Ball and Pokémon faint sound effects after setting the solo/private battle mix to 75% of the previous cry volume and 110% of the previous effects volume. Both new cues use the existing SFX bus and Sound / Move sounds controls. They do not use the Pokémon cries toggle, and move preview has no transition sounds.

The sound collection contains `In-Battle Recall Switch Pokeball.mp3` and `In-Battle Faint No Health.mp3`. The host explicitly reuses the first recording for ball activation at send-out opening; it is not claimed to be a dedicated release recording. `battle.release.pokeball` retains its raw `battle.recall.pokeball` source identity. The faint recording maps directly to `battle.faint`. Both play the complete original native buffer at normal speed and 0 dB per-voice gain, followed by the battle-effects mix. Source recordings, raw candidate metadata, accepted move plans and historical listening evidence remain unchanged.

The Poké Ball clip emits one cosmetic `open` cue per actor at its opening frame, separately from the existing reveal/cry cue. The faint clip emits one `faint` cue per actor when its timeline starts. FX receives no sound player or battle state. The scene and presenter validate the retained member, current operation and visibility before forwarding the cue to host audio. Faint cues include the exact outgoing member ID even when the server has already cleared its active slot.

Opening send-outs, switches and forced replacements work from either viewer seat. Reduced motion uses its first visible entry/faint frame. Effects-off, reconnect, same-lineup correction and stale callbacks do not synthesize transition cues. Host event keys prevent duplicates; a missing or invalid buffer is skipped without delayed playback. Normal completion permits natural tails. Skip, reset, mute, hidden tabs, supersession and disposal stop owned voices.

`eventAudio.js` shares whole-buffer validation, deduplication and cleanup between transition and effectiveness cues. The runtime catalog contains four original assets totaling 180,230 bytes. Generate/check them with `npm run sfx:events` / `npm run sfx:events:check`. Focused tests cover native rates, both seats, transition frames, retained fainted actors, cancellation, stale callbacks and production asset delivery.

Browser verification on 2026-09-19 used `tests/fixtures/transition-audio-browser.html` with the real scene, presenter, audio factories and native Web Audio. Solo and private hosts each produced two ball voices and one faint voice, all at native speed with natural completion; fainting followed the zero-HP reveal. This is playback evidence, not a listening approval. The 987 application tests, 36 SFX package tests, event/accepted asset checks and production build passed.
