# Agent guide: Pokémon battle animations

## Scope and working style

This is a Vue 3, plain JavaScript, PixiJS 8 and GSAP 3 workspace with 309 registered moves. Preserve all active moves and the existing visual direction unless the user requests a redesign. Water Gun now has an active standalone recipe; its older `examples/` copy remains inactive teaching code. Do not duplicate an existing move.

The user prefers focused iteration: inspect the relevant source, change the animation, check its contact and cleanup, build once, and publish the existing demo when authorized. Defer full ZIP exports, fresh installations, broad regression runs and full document refreshes for ordinary visual tweaks. A package or lifecycle change warrants the relevant integration tests; this migration updated the full guides because every layer changed. Use `rg`, preserve unrelated edits, and keep progress updates brief.

Higher-priority instructions and the user's current request override this guide. Retain `.openai/hosting.json` and the existing Site identity. Do not add a framework, convert to React/TypeScript, or install a dependency without a concrete reason.

## Boundaries that must remain true

- `packages/battle-core` owns immutable battle state, move rules, results, condition changes and accuracy stages. It must import no renderer, browser API, Vue, presentation code, or FX package. Toxic uses `bad-poison`; Smokescreen lowers `accuracyStage` by one, bounded to −6…6. Ongoing poison damage and accuracy rolls remain outside this preview.
- `resolveMove()` returns `{ before, after, event }`. The host commits `after` immediately; animation is optional presentation of an already-decided result.
- `packages/battle-fx` knows move IDs, actor IDs, cosmetic outcomes and a visual seed. It must not receive mutable battle state or apply HP, statuses, turn changes, PP, or rule RNG. It must not import the game app, core package, Pokémon sprite URLs, or Vue.
- `apps/game/src/presentation/presenter.js` owns presentation ordering and displayed snapshots. Impact cues may reveal the committed result; they cannot recalculate it. Completion, skip, failure and timeout reconcile the same result.
- `apps/game/src/scene` owns base rendering, actor profiles and layout. Effects are dynamically imported separately. Base rendering must not load effect artwork.
- `apps/fx-playground` plays effects directly and must not import battle-core or the battle presenter.
- Host UI descriptions live in `moveDetails.js`; battle rules and FX registration remain independent. A valid battle move with no registered animation still resolves.

## Either side can act

All 309 moves support both perspectives. Stable scene IDs are field identities; `request.sourceId` is the selected move user and may refer to the far-side actor. Never swap actor IDs/artwork or mirror the camera to fake an opponent move. Keep preview fixtures, messages, HP and every badge symmetric, using the selected actor ID. Side/species changes must cancel old playback and reject stale display/completion updates. `PokemonInfo.vue` renders the same state fields for either side. Keep move details and Use controls above the grid.

Host anatomy owns native-facing conversion: mirror fallback sockets for left-native art, then merge explicit profile/custom sockets unchanged. Merge partial `spec.anchors` over the profile; do not drop measured emission/origin metadata. Use `visualCenter` for geometric pivots/bounds and semantic `center` for aiming. Scene URLs/textures and learnset filtering stay outside FX. `createPreviewTransaction` accepts optional host-supplied `allowedMoveIds`; the showcase itself remains unrestricted. See `docs/OPPONENT_PREVIEW.md`.

The preview roster is limited to the nine Kanto starter evolutions. Restore native pixel-art proportions using the original near/far scale (265/96 and 235/96 at 1000×450), with visible-height floors of 150 near and 125 far for smaller sprites. The original Charizard-back and Venusaur-front dimensions remain 229.114583 and 168.90625 high. Do not reintroduce fixed size classes, 20% steps, equal Charmander/Charizard sizing or a Venusaur multiplier; the user retracted those requests. Do not use Pokédex physical measurements. `previewSceneActors` assigns back artwork to the near position and front artwork to the far position, independent of the current attacker. Resolve the selected view for both loading and anatomy; preserve the original Charizard-back/Venusaur-front sockets. `spriteViews.js` owns the 18 measured PNG profiles. Keep all move art/timing unchanged when editing sprite selection or sizing. The playground uses the same default scale and minimums, including in alternate logical layouts.

Ground platforms belong to the scene layout, never actor metrics or anatomy. Fixed radii are 173×38 near and 143×31 far, scaled only by scene.unit. Center each platform exactly at the sprite's visible bottom-center slot position at rest. Species selection, manual sprite scale and animation poses must not change its dimensions or position. Do not use the legacy `floor` socket to position platforms; preserve that socket for approved move geometry.

Ground effects need the actual source-to-target floor slope, and projectiles need the actual vertical direction; horizontal mirroring must never reverse gravity or readable glyphs. Preserve calibrated default coordinates when adapting the restored originals. The optional scene depth hook only changes draw order during a rear actor's close approach and must reset on all exits. The 93 unchanged reference frames and Waterfall visibility/crop checks are gates for shared coordinate changes. `tests/opponent.test.mjs` covers every move in both field positions across all nine starter species, reflection invariants, recovery/status routing, cancellation and reduced motion.
